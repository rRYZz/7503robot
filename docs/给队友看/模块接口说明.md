# 模块接口说明：第二队（简化版）

这是组内接口约定，不是老师指定的 API。固定按 A→B→C→D 搬运。第二队真实二维码填写到 `targets_robot.yaml`。地图、坐标、朝向和路线全部由导航模块自行管理。

## 队友只需遵循的基本规则

```text
收到任务 → 执行动作 → 完成并停止后返回成功
                    → 做不到返回失败和原因
收到停止 → 停止当前动作 → 停止完成后返回结果
```

主程序信任模块的完成结果，不再额外核对静止、升降传感器来源或安全令牌。不要在仅收到命令时返回成功，成功表示动作已经完成。

## 接口表

通用 mock 模拟通信域 62、Gazebo 联合仿真域 0，命名空间均为 `/team2/sim`；实机通信域 42、命名空间 `/team2/robot`。配置使用相对名称，所有协作模块使用同一通信域和命名空间。定位导航及底盘实测反馈的完整交接见 [导航接入与部署](../导航接入与部署.md)。

| 任务 | 相对名称 | ROS 类型 | 队友提供什么 |
|---|---|---|---|
| 导航 | `navigate_to_point` | `mission_interfaces/action/NavigateToPoint` | 收到 A/B/C/D/DROP_OFF，自己执行导航；到达并停止后返回 Action 成功及 `success=true`，失败写原因 |
| 扫码 | `qr/detections` | `std_msgs/msg/String` | 发布完整二维码及图像时间，格式见下文 |
| 对准进入／退出 | `docking/execute` | `mission_interfaces/action/Dock` | ENTER 完成进入并可托举，EXIT 完成退出；返回 `success` 和说明 |
| 升降 | `lift/set_up` | `std_srvs/srv/SetBool` | `data=true` 升、`false` 降；做完返回 `success` 和 `message` |
| 升降显示（可选） | `lift/is_up` | `std_msgs/msg/Bool` | 显示位置，不参与主程序完成判断 |
| 在线反馈 | `robot/status` | `std_msgs/msg/String` | 定期发布 `ready` 和 `fault` |
| 整机停止 | `safety/stop` | `std_srvs/srv/Trigger` | 停止当前执行动作，完成后返回 `success` 和 `message` |

## 导航与对准

导航只接收一个字段 target_id，值为 A、B、C、D、DROP_OFF（放置区）；实机与 Gazebo 联合仿真的 scan_route 配置还发送 START_SCAN、FINAL_SCAN。主程序不发送坐标、坐标系、朝向或路线。本仓库 robot_navigation 已提供导航、进退架和树莓派轨迹跟踪；底盘组接速度指令，升降组接机构服务，无需另写进退架运动服务。

```text
主程序：去 A → 导航模块自己查 A 的位置、规划路线并到达 → 返回成功
主程序：完成拿取后去 DROP_OFF → 导航模块自行到放置区 → 返回成功
```

导航队友维护 A/B/C/D 四个货架接近点和 DROP_OFF 放置区点，自己决定地图坐标系、坐标与到点朝向。A/B/C/D 到达位置应适合后续识别 QR 和进入货架；DROP_OFF 到达位置应适合放下。定位、规划、避障均由导航模块实现。

动作定义在 `src/mission_interfaces/action/NavigateToPoint.action`。结果只有 `success`、`message`；`phase` 是可选进度显示。到达并停止后设置 `success=true` 并将 Action 结束为成功；失败设置 false、填写原因并结束为失败。不要求额外错误码、回传坐标或第二份到点确认。

如果队友内部使用 Nav2，可以在自己的模块里将点位名转换为位姿并调用 Nav2；对主状态机仍只提供这个点位接口。旧 NavigateToPose 不能直接连接新版客户端，需要队友提供这一层点位接口。

对准目标包括 request_id、operation、rack_id、expected_qr、max_duration_sec。主程序填写这些字段，本包导航使用 ENTER／EXIT 和当前货架信息执行，并与状态机当前请求关联。请求编号用于关联日志，不要求额外编号确认服务。进退架与普通导航通过同一个 TrackPath 跟踪器发送 /cmd_vel，平台升降由 lift/set_up 独立执行。

对准成功条件由模块自己负责：ENTER 成功表示可托举；EXIT 成功表示已脱离。主程序只使用 Action 最终成功和结果 `success=true`。现有动作定义中的 `ready_to_lift`、`exited` 保留作兼容／显示，不再是额外必填成功条件。

导航和对准支持标准 Action 取消：取消后停止动作并结束任务。主程序自动过滤旧结果，停止成功后不等待旧回执才能重试；迟到接受的旧目标仍会被取消。无需队友另写一套确认握手。

## 底盘速度输出

底盘速度接口另见 [导航接入与部署](../导航接入与部署.md#esp32-接什么数据)：导航已提供 Twist→JSON 转换，实机输出 /team2/robot/base/cmd_vel_json（std_msgs/String），通信模块将 data 内的 linear/angular JSON 发给 ESP32。此速度消息和下面的 QR JSON 是不同话题与不同数据结构。

## QR 输出

```json
{
  "image_stamp": {"sec": 1791450000, "nanosec": 100000000},
  "status": "ok",
  "detections": [{"raw": "RACKA_实际后缀"}]
}
```

使用真实图像时间和本队完整 QR。没有标签时 `detections: []`，识别失败时使用其他 `status`。可保留已有节点的角点等额外字段。

主程序自动处理三帧确认和旧图像过滤，队友无需增加人工确认。跨电脑发布图像时保持系统时钟一致。QR 识别与局部对准是不同任务。

已有全局话题可重映射到当前机器人，例如：

```bash
python3 ~/camera_qr/qr_node.py --ros-args -r /qr/detections:=/team2/robot/qr/detections
```

## 升降

请求就是 `SetBool.Request.data`，返回 `success`、`message`。不需要请求编号、安全令牌、去重表、健康消息中的到位字段或实测／推定来源。

升起完成后返回成功，主程序进入运输；放下完成后返回成功，主程序记录交付并退出货架。失败则停止流程，不自动发送反方向动作。限位开关、行程时间等实现方式由升降模块根据实际机构选择。

Service 没有 Action 取消能力，因此整机停止接口需要通知升降停止或按机构方案保持。客户端超时会忽略旧结果；它不能撤回已经发送的服务请求。本版不再使用令牌拦截停止后晚到的旧升降请求。

## 简单在线反馈与停止

```json
{"ready": true, "fault": ""}
```

整机集成端统一发布即可，不需要每位队友输出五个模块字段。`ready` 表示执行模块就绪，`fault` 为空表示没有故障；发现问题填简短原因。建议每秒 5～10 次，默认超过 2 秒未收到消息视为断联。可以省略 `fault`，默认空字符串；额外字段会忽略。

不要求 `schema_version`、源时间戳、`stopped`、`lift_is_up`、`lift_state_source` 或令牌。在线反馈只判断就绪／故障，不作动作完成后的第二次确认。

`safety/stop` 由整机控制端协调导航、对准、升降和底盘。成功表示已执行停止，主程序收到成功就结束停止等待，不再等待额外状态或旧回执。主程序自身也发送 Action 取消。

## 主程序状态与人工入口

mission/status 包含当前阶段、货架、请求编号、剩余时间、重试次数、原因、delivered、completed 和 cargo。主状态机根据升降完成结果更新 cargo；导航读取当前 NAV_END 货架以选择投放点，并用当前 Dock 请求关联进退架操作。状态话题不要求队友另发确认服务。导航内部使用 base/feedback 的实测平台和停止信息，格式见 [导航接入与部署](../导航接入与部署.md)；主状态机仍直接使用各模块完成结果。

mission/arm 启用本轮；实机/联合仿真的 scan_route 配置先前往起点前方旋转扫码，通用 mock 直接等待 START。mission/stop 请求停止，两者使用 Trigger。注意 mission/stop 的立即响应表示接收请求，最终停止结果查看 mission/status.stop.status；底层 safety/stop 的成功响应才表示停止完成。

停止结果为 `NOT_REQUESTED`、`PENDING`、`CONFIRMED`、`FAILED` 或 `TIMED_OUT`。故障原因保留；再次停止成功会独立显示。停止未确认时退出会再补一次有时限的请求，不无限重发。结束后不再持续检查静止反馈。

通信域、目标配置、接口名称和消息字段的基本格式检查仍保留，避免接错模块。完整流程见 [任务流程说明](任务流程说明.md)，单模块命令见 [单模块测试说明](单模块测试说明.md)。
